Just think about it

Every day, you type a password into an app or a website. And websites get broken into all the time — you've probably seen the headlines: "millions of passwords leaked."

So here's the puzzle: a site needs to check your password when you log in, but it really doesn't want to keep your password anywhere a thief could grab it. If it stored a list of your actual passwords, a break-in would hand the thief thousands of real ones.

How could a website recognise that you typed the right password... without ever keeping the password itself?

The big reveal

The Fingerprint Machine is called Hashing

🧠

When you signed up, the machine ran a hash function: it squeezed your password into a fixed-size fingerprint — a hash value. The website never kept your password. It kept only this fingerprint. On login it squeezed the same password again and compared the two fingerprints. Same code → welcome back. Different code → wrong password. Fast, tiny, and there's no road back.

One-way · fast · fixed size
password  ➜  🖐️ hash function  ➜  fingerprint

Same password ➜ same fingerprint. Different password ➜ almost always a different fingerprint. And here's the magic: you can hash() in one direction only — from a fingerprint you cannot recover the password.

Hash function
A machine that turns any input into one fixed-size fingerprint. Operates on whatever you feed it — a password, a file, a whole book.
Hash value
The fingerprint itself — the short code that stands in place of the original data.
One-way
The direction you can travel: input ➜ fingerprint. There is no finger-print ➜ input path.
Collision
When two different inputs land on the same fingerprint — your CAT and ACT.
🙅 The old, bad way
Store the password. A break-in hands the thief the real, reusable passwords.
✅ The hashing way
Store only fingerprints. A break-in finds nothing reversible back to your password.

Where you already meet hashing in the real world

  • Logging in — nearly every website and app stores a hash of your password, never the password itself.
  • Git — every commit gets a 40-character hash. Change any file and the hash changes, so history can't be silently tampered with.
  • Downloads — software sites publish a file's hash. After downloading, your computer hashes the file and compares the code to catch corruption or tampering.
  • Digital signatures & blockchain — hashes are the glue verifying that data is exactly what it claims to be.
  • Fast lookups inside apps — search bars, caches and duplicate-file finders use hashes to locate things instantly instead of scanning everything.
